# M2 静态 Excel 报告契约

日期：2026-10-24。应用版本 `0.2.0`，核对规则 `v1`，报告格式 `m2-v1`。本文件补充冻结的核对规则，不更改编号、金额、隔离和配对含义。

## 接口和成功条件

`sheetcheck.export_xlsx(result) -> bytes`：先运行 `assert_invariants`，生成完整工作簿，在内存中扫描 ZIP/XML 并重新打开逐单元格核验，通过后返回字节。调用方不能获得绕过审计的“成功报告”。`sheetcheck.audit_xlsx(data, result) -> None` 可对保留的字节再核验；它需要对应的完整 `ReconciliationResult`，JSON 导入目前不是公共接口。

`sheetcheck.report_filename(result)` 生成 `sheetcheck_YYYYMMDDTHHMMSSZ_<32位run_id>.xlsx`；时间统一为 UTC，拒绝无时区时间及不合法 run_id，不引用源文件名或路径。

报告 API 不读取或写入路径、不访问网络。CLI 的 `--export-dir` 才授权保存到指定的已有目录；先完成内存导出和审计，再以独占创建写入，拒绝已有文件及符号链接，刷新并同步文件后报告成功。写入失败/取消时尽力删除本次创建且身份未变的部分文件，不能承诺进程被强杀或系统断电后仍能清理。失败不输出成功 JSON。

## 五个固定页签

顺序固定；各页均可见，有表头、筛选、冻结窗格和文本状态。状态含义不依赖颜色。

| 页签 | 行粒度及字段 |
| --- | --- |
| 运行说明 | 四列：分区、字段、值、说明。保存应用/规则/报告版本、run_id、输入与参数指纹、起止时间、币种/期间确认、所有规则、两侧输入信息/限制/哈希、表头/前言/映射及原表头、计数/金额/覆盖风险、转义规则 |
| 业务结果 | 一条配对或单侧结果一行；25 列，含状态、编号、两侧两位小数金额及整数分、差额、result_id、两侧 source_id/文件/sheet/源行/CSV物理起止行/映射列 |
| 异常明细 | 与业务结果相同字段，仅 `AMOUNT_MISMATCH`、`ONLY_ORDER`、`ONLY_PAYMENT` |
| 数据问题 | 每条 `DATA_ISSUE` 源行一行；23 列，为账本字段加修复建议。所有问题码在一个 JSON 数组内，多问题不复制行 |
| 源行账本 | 每条输入记录恰好一行；22 列，含状态、角色、原始编号/金额、可解析金额、问题码/规范化说明、source_id/result_id、匹配编号、原始类型、文件名/SHA-256/sheet/位置/映射列/隐藏行标志；包括 `SKIPPED_EMPTY` |

准确列序、标题、宽度由 `sheetcheck/report_schema.py` 定义。空结果仍保留五页与表头。

### 从结果回到源行

1. 在“业务结果”或“异常明细”取得对应侧 `source_id`，在“源行账本”筛选同值，得到唯一源记录；`result_id` 连接配对的两条账本记录。
2. 核对原文件 SHA-256；按文件角色/文件名区分两侧。XLSX 使用原工作表、Excel 行号和原列号定位；CSV 使用包含表头的逻辑记录号及物理起止行定位，引号换行记录可跨多行。
3. 对照原始值、类型、解析分值与规范化说明。问题源行按同样方法查回，不会伪造业务 result_id。源行在多个页签出现是引用关系，不意味着重复计数。

只导出映射字段的原值和必要元数据，不复制无关列或其公式。原始数值按解析库读取值转文本并另列类型；日期使用 ISO 文本，无法从上游损坏或 Excel 已丢失的精度恢复原始字符。

## 金额与空值

- 业务和账本的金额提供整数分及两位小数字符串。差额固定为收款减订单，允许负数。计算使用已有整数结果，导出不做浮点运算。
- 单侧缺失金额、差额及来源字段为真正空单元格；零金额为数值 `0` 分、文本 `0.00`。不得把缺失填零。
- 原始空字符串与不存在不同：前者编码为 `SC_ESC:""`，后者为空单元格。
- 静态汇总来自已审计 manifest。可核对金额与问题可解析部分分列，另记问题金额不可解析行数。
- Excel 数字只有 15 位有效十进制精度。汇总整数绝对值达到 `10**15` 时，用格式 `@` 的精确十进制文本保存并在说明列标记；对应金额显示仍为精确两位小数字符串。单笔金额受内核上限约束，不会达到此阈值。已用真实 10001 行合法输入验证 16 位汇总，而非伪造 manifest。

## 可逆文本编码

编号、原始金额、文件名、工作表名、期间、表头等用户字符串写为明确的字符串类型和文本格式 `@`，覆盖 openpyxl 对 `=` 和 `#N/A` 的自动类型推断。以下字符串额外编码为 `SC_ESC:` 加 `json.dumps(original, ensure_ascii=True)`：

- 忽略前导空白后以 `=`、`+`、`-`、`@` 开始；首字符为 Unicode 控制/格式/代理字符。
- 含 XML 不允许的控制字符、回车、代理字符或 U+FFFE/U+FFFF 等平面末尾非字符。
- 原值本来以 `SC_ESC:` 开始，或原值为空字符串。

普通中文、Unicode 和非首位换行可以保留原显示。内部生成的负差额文本如 `-1.00` 直接保存为文本，因为它不是用户可注入的表达式。编码不改变内存中来源对象或业务匹配值。

```python
from sheetcheck.report import encode_text, decode_text

original = '=HYPERLINK("https://invalid.example")'
safe = encode_text(original)
assert decode_text(safe) == original
assert decode_text(encode_text('SC_ESC:"x"')) == 'SC_ESC:"x"'
```

只解码一次。来源字段以 `SC_ESC:` 开始即读取后面的 JSON 字符串；不要对解释性文字或 `problem_codes` 等结构化数组应用此规则，也不要把解码结果重新按公式写入另一个工作簿。

编码后超过 32,767 个 UTF-16 单位会抛 `EXPORT_TEXT_LIMIT`，不截断字段。该限制可能拒绝内核能读取的长 CSV；超长输入需修正后重新核对。极长文本即使在单元格内完整保存，也可能超过 Excel 行高 409 磅的可见范围，可在编辑栏查看全文。

## 回读安全和完整性审计

审计在返回字节前必经，独立入口也先验证内核不变量。检查包括：

1. ZIP 恰好包含本格式生成的 13 个部件，拒绝缺失、额外、重复、加密或不支持的压缩类型；报告压缩后最多 128 MiB，XML 展开合计最多 512 MiB，XML 深度最多 64。
2. 使用 defusedxml 禁止 DTD、实体和外部引用；拒绝单元格公式、条件格式公式、验证公式、超链接、外链、OLE、宏/活动内容及不支持的工作表/工作簿顶层结构。
3. 关系仅允许固定本地目标。唯一允许的定义名称是五个准确的 `_xlnm._FilterDatabase` 静态筛选范围，校验名称、sheet 索引、范围和唯一性；任意其他名称或表达式均拒绝。
4. 严格检查行/列坐标顺序、数量、尺寸和可见性，拒绝重复行/单元格、超界内容和隐藏来源。
5. openpyxl 以 `read_only=True, data_only=False` 重新打开，核对五页名称与顺序、全部列标题、每个静态值/原值编码/源位置/身份、空值、整数类型、文本类型与格式。所有金额和计数必须与已审计结果逐项相同。

这能发现预期格式内的导出错误和测试覆盖的篡改，不是任意工作簿扫描器，也不证明源文件真实。报告不是数字签名；他人修改后应重新与可信原输入核验。

## 实现边界与维护

openpyxl 的默认保存流程即使目标是 `BytesIO` 仍会建立工作表磁盘临时文件。本项目针对锁定的 3.1.5 使用 `WorksheetWriter(out=BytesIO())` 的适配器，将 XML 直接写入内存 ZIP。测试禁止文件打开、临时文件创建和 socket 后完成 CSV/XLSX 结果的导出与审计。升级 openpyxl 之前必须重新跑此测试及整套导出回归。

128/512 MiB 是容器拒绝阈值，不能当作进程峰值内存保证；写入阶段会持有单元格对象图。同步任务可用 Ctrl+C 取消，尚无自动超时。允许输入上限的全面压力测试、原生 Excel/LibreOffice 与跨平台兼容、M3 页面下载和 M4 整机断网观察仍待实施。

参考：[openpyxl 单元格绑定实现](https://openpyxl.readthedocs.io/en/stable/_modules/openpyxl/cell/cell.html)、[openpyxl 优化读写模式](https://openpyxl.readthedocs.io/en/stable/optimized.html)。实际依赖版本以 `requirements.lock` 为准。
