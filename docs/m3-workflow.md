# M3 页面使用与恢复指南

适用版本：应用 0.3.0、规则 v1。本指南说明如何操作页面；实际通过的测试及其范围见 [M3 验收记录](m3-verification.md)。全部内置样例都是虚构数据。

## 启动本机页面

按 [README](../README.md) 安装依赖后，在 SheetCheck 项目目录执行：

```sh
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8501`。保持启动终端运行，结束时按 Ctrl+C。页面使用本机 HTTP 服务；文件上传到运行此服务的机器，所以不要改为监听 `0.0.0.0`、公网分享或远程部署。

当前锁文件与干净安装证据针对 CPython 3.12 / macOS arm64。换系统或架构时，需要另外验证依赖和锁文件。系统级断网、网络流量观察和原生 Excel 兼容仍属于 M4 验收范围。

## 先完成一次虚构样例

1. 点击侧栏“加载虚构样例”。左右分别显示 `orders.csv`、`payments.csv`、字节数、读入选项和前 20 条预览。样例预选第一列为编号、第二列为金额，并填入虚构期间。
2. 检查每侧字段示例。编号保持文本，不能把编号列和金额列选成同一列。币种默认 CNY；样例也需要手动勾选“我确认两个文件属于同一币种”和“我确认两个文件属于上述同一核对期间”。
3. 点击“开始核对”。预期得到 2 对一致、1 对金额差异、1 条仅订单有、1 条仅收款有，以及 6 条问题源行。业务结果共 5 条，源行账本共 14 条；订单可核对金额 180.00，收款 189.00。
4. 在分类中选择“金额差异”，可看到 A002，订单 50.00、收款 49.00，差额为 -1.00。差额定义始终是“收款减订单”。
5. 在“查看来源详情（当前页）”选择该结果，核查两侧文件名、源行、映射列及原值。展开“完整来源、原始类型与问题修复建议”，可查看 source_id、result_id、文件 SHA-256 和原始类型。
6. 切换“数据问题”检查隔离原因。问题行不计入可核对金额；“可解析部分”也不是完整问题金额。缺项只描述本次有效集合，不能直接解释为欠款。
7. 点击“生成报告”，等待导出与回读审计完成，再点击“下载核对报告”。报告包含“运行说明、业务结果、异常明细、数据问题、源行账本”五页。

预期答案独立保存在 [samples/expected.json](../samples/expected.json)。这一样例不足 100 条，因此只有一页；分页检查使用更大的虚构测试数据，实际测试范围见验收记录。

## 导入自己的文件

左右上传控件分别对应订单表和收款表，每份支持 CSV/XLSX，最大 10 MiB。文件扩展名筛选只是入口；读入时还会检查文件格式、容器和容量限制。

- XLSX：选择工作表及表头行。多工作表不要凭文件名推断。编号、金额或映射表头涉及公式、数组公式或合并区域时不能核对；请从可信来源导出普通值副本。
- CSV：选择 UTF-8 / UTF-8 BOM、UTF-8 或 GB18030，以及逗号、制表符或分号。预览乱码时检查编码；内容集中在一列时检查分隔符。表头行表示逻辑记录号，带引号换行的记录可能跨多条物理行。
- 字段映射：选择项包含列号和原表头。空表头、重复表头也以列号区分。预览最多 20 条，较长字段只是显示缩短，未改写原始值；来源详情及报告保留可追溯信息。
- 规则确认：填写实际核对期间并确认同币种、同期间。程序根据你的声明运行，不会自动核实业务系统中的覆盖范围。

请先修正源数据，再重新导入；页面不提供直接改金额的编辑功能。不要仅改变 Excel 显示格式来修复数值型编号，因为这不能恢复已经丢失的前导零或精度。

## 分类、搜索与分页

分类包括全部业务结果、金额差异、仅订单有、仅收款有、数据问题。业务状态筛选只影响业务结果；数据问题单独按源行展示，同一行的多个问题码不会重复计数。

编号搜索区分大小写，使用包含匹配。例如 `A00` 可找到包含该文本的编号，`a00` 不会等同于 `A00`。搜索和筛选只改变当前显示，不重新计算金额或改变业务分类。

每页最多 100 条，服务端只向结果表发送当前页。页码限制在有效范围内；更改分类、搜索或筛选后回到第一页，并清除旧的来源详情选择。没有匹配项时显示空结果说明，不能把它理解为没有业务差异。

来源详情只能从当前页选择。业务结果显示实际存在的两侧来源；单侧结果缺少的一方保留为空，不能当成零金额。数据问题详情显示该条源行及全部问题码。

**完整报告不受当前分类、搜索、状态筛选或页码影响。** 即使页面只显示 A002，下载仍包含该次核对的全部结果和源行账本。

## 输入改变、重置与下载

以下任一更改都会立即撤销旧结果及旧报告：

- 替换或删除任一上传文件，包括同名但内容改变的文件。
- 更改工作表、表头行、CSV 编码或分隔符。
- 更改任一字段映射、币种、期间或任一确认项。

更改后需重新核对，再生成新报告。页面拒绝把旧输入的晚到操作结果恢复为当前成功状态，旧下载请求也必须对应当前有效报告。浏览器已经接收或保存的文件不受页面控制，不能被撤回。

“重新开始”会清空本会话的上传、样例、读入选择、映射、确认、筛选、页码、来源详情、结果和报告。加载样例也会先重置当前会话。刷新浏览器可能丢失未下载工作，关闭应用也不是保存操作。

应用默认不把上传内容、核对结果或待下载报告写入项目磁盘，不使用跨会话缓存存放业务数据。点击下载后，保存位置由浏览器决定。重置只是释放引用，不宣称安全擦除内存、系统交换区或浏览器下载记录。已经下载的文件请自行管理。

## 遇到错误时

| 现象 | 下一步 |
| --- | --- |
| “开始核对”不可用 | 检查两侧文件是否成功读入、编号与金额是否映射为不同列、期间是否填写、两个确认框是否勾选。 |
| 编码错误、乱码或一列包含整行 | 调整 CSV 编码/分隔符并查看预览，再重新选择映射。 |
| 读入提示公式、合并区域、外链、损坏或活动内容 | 从可信来源重新导出普通值文件后上传；不要尝试让应用计算公式或打开外链。 |
| 读入暂时失败 | 保留输入，使用相应侧的“重试读取”按钮；若重复失败，按错误码检查文件或重新导出。 |
| 显示“输入或核对设置已更改”或 `OPERATION_STALE` | 当前旧结果已失效。确认最新文件及选项，重新核对；不要使用先前保存的报告代表新输入。 |
| 编号重复、坏金额或 `BLOCKED_ID` | 查看问题源行与修复建议，在源系统修正。某编号关联行有问题时，该原样编号在两侧全部隔离，不会合并或择一计算。 |
| 报告生成失败 | 不会出现已审计成功的下载。当前输入仍可检查；按提示修复后重算、重试，或重新开始。 |
| `EXPORT_TEXT_LIMIT` | 转义后的字段超过 Excel 单元格上限。缩短源字段后重新核对；程序不会截断后报告成功。 |
| 刷新后数据消失 | 重新导入并核对。未主动下载的结果没有自动保存副本。 |

报告内容涉及源字段原值，请按原账表的敏感程度保管。页面关闭使用统计及表格内建 CSV 导出，下载统一通过安全 XLSX 报告；这些配置不等于对所有环境完成了系统级网络或文件安全验收。
