# 第一次使用 SheetCheck

**SheetCheck 帮你核对两张表：订单里写了多少，收款里记了多少，哪些记录需要回头查。** 你提供一张订单表和一张收款表，指定各自的编号列、金额列，它会按相同编号逐条比较，并给出能追溯到原始行的 Excel 报告。

例如，你导出了同一个月的订单和收款。订单 `A002` 是 `50.00`，收款表里也是 `A002`，但金额是 `49.00`。SheetCheck 会把它列为“金额差异”，显示差额 `-1.00`，方便你回到两张原表检查原因。它不会判断这 1 元是不是欠款、手续费或录入错误。

适用前提是：**两张表属于同一币种、同一期间，每个编号在每张表中最多出现一次。** 不需要两张表行顺序相同，也不需要列名相同。

## 先用虚构样例走一遍

第一次使用可以先不准备文件。打开本机页面后按下面五步操作，所有内置样例都是虚构数据。加载样例会清空当前会话中的输入和结果。

1. **加载两张样例表。** 点击首页“用虚构样例试一遍”，或侧栏“加载虚构样例”。左侧是订单表，右侧是收款表，预览中可以看到 `A001`、`A002` 等编号和金额。
2. **检查列与核对范围。** 样例已选好编号列、金额列，并填入“虚构样例期间”。检查两侧映射示例，保持币种 `CNY`，手动勾选同币种、同期间两个确认框。这些确认表示你检查过文件范围，程序不会替你核实业务期间。
3. **开始核对。** 点击“开始核对”。样例预期是 **2 对一致、1 对金额差异、1 条仅订单有、1 条仅收款有、6 条数据问题源行**。可核对金额为订单 `180.00`、收款 `189.00`；数据问题不计入这两个金额。
4. **找一条记录并追溯。** 点击“查看金额差异”（或在“结果分类”选择“金额差异”），找到 `A002`：订单 `50.00`、收款 `49.00`、差额 `-1.00`。再在“查看来源详情（当前页）”选择它，查看两侧原始行。点击“先看数据问题”会看到重复编号、空编号和坏金额等问题；选择问题行并展开详情，查看修复建议。快捷按钮会清空旧搜索和筛选条件，不改变核对结果或报告。
5. **生成并保存报告。** 点击“生成报告”，等待回读审计完成，再点击“下载核对报告”。报告包含“运行说明、业务结果、异常明细、数据问题、源行账本”五个工作表。生成成功表示报告已准备好；要保留文件，仍需完成浏览器下载。练习结束后点击“重新开始”，再导入自己的两张表。

样例的独立预期答案见 [expected.json](../samples/expected.json)。

## 换成自己的两张表

准备 CSV 或 XLSX 文件，每份不超过 **10 MiB、50,000 条数据记录、100 列**。两张表至少各有一列编号、一列金额；其他列可以保留。以下是最小例子：

| 订单编号 | 订单金额 |
| --- | --- |
| A001 | 100.00 |
| A002 | 50.00 |

| 收款对应编号 | 实收金额 |
| --- | --- |
| A002 | 49.00 |
| A001 | 100.00 |

- **编号要能在两张表间对应。** 编号按原文本精确匹配：`00123` 与 `123` 不同，`A001` 与 `a001` 也不同。Excel 中的编号应保存为文本；只改变显示格式无法恢复已经丢掉的前导零。
- **金额用普通数值。** 例如 `100`、`100.0`、`100.00`，零也有效。不要带 `￥`、千分位逗号、负号或超过两位的小数。程序不会换算币种或替你四舍五入。
- **每侧各选两列。** “编号列”是用来找同一笔记录的字段，“金额列”是要比较的金额，两者不能选同一列。读完预览，再核对下方映射示例。
- **预览不对时调整读取选项。** XLSX 选择正确的工作表和表头行；CSV 乱码时检查编码，整行挤在一列时检查分隔符。每侧预览只展示前 20 条，隐藏行也会参与核对。
- **填写真实核对期间再确认。** 两张表必须使用相同币种、相同覆盖期间。期间是你的说明，填写日期不会自动筛掉文件中范围外的记录。

经常使用相同导出格式时，可以启用“使用映射模板（可选）”。第一次使用无需设置。模板只记住列位置等配置，不能判断列含义是否改变；应用后必须重新检查并确认。详见 [映射模板说明](mapping-templates.md)。

## 结果应该怎么看

先看“数据问题”，确定哪些行没有参与金额核对，再查看金额差异和单侧记录。

| 页面分类 | 含义与下一步 |
| --- | --- |
| 一致 | 两侧编号和金额相同；只说明这次输入中的可核对记录一致。 |
| 金额差异 | 编号相同、金额不同。差额始终是“收款减订单”，负数表示表内收款金额较小。查看两侧原值和来源，再判断业务原因。 |
| 仅订单有 / 仅收款有 | 在本次有效记录中没有找到另一侧。检查是否漏导、期间不同或关联行被隔离，不能直接当作欠款或多收款。 |
| 数据问题 | 这一源行无法可靠参与核对，例如编号重复、编号缺失或金额格式错误。先查看原因，在源表或源系统中修正后重新导入。 |
| 空行跳过 | 全空数据行不参与金额核对。 |

同一编号只要有关联行出错，它在两侧的记录会一起隔离；例如样例 `A006` 的订单金额是 `X`，收款表中的 `A006` 也不会单独参与核对。问题金额的“可解析部分”只是能读懂的部分，不是完整问题总额。

分类、编号搜索和分页只改变当前显示。每页最多 100 条，搜索区分大小写；**下载的报告始终包含本次完整结果**，不受页面筛选影响。没有搜索结果不代表没有差异。

## 卡住时先检查什么

| 现象 | 怎么继续 |
| --- | --- |
| “开始核对”不能点击 | 两侧文件都要成功读入；分别选择不同的编号列、金额列；填写期间并勾选两个确认框。按页面待办逐项完成。 |
| 公式、合并区域或文件格式被拒绝 | 从可信来源导出普通值 CSV/XLSX，再重新上传。应用不计算公式；编号、金额及所选表头不能涉及公式或合并区域。 |
| 结果出现很多“仅一侧有” | 检查编号列是否选错、编号大小写及前导零是否一致、两表期间是否相同，以及数据问题是否影响配对。 |
| 改了输入后结果不见了 | 这是正常行为。更换文件、读取选项、映射或规则后旧结果失效，需要重新核对和生成报告。 |
| 报告还没有下载按钮 | 先完成核对并点击“生成报告”。只有生成与回读审计成功后才提供“下载核对报告”；失败时按页面提示检查或重试。 |
| 刷新或重置后内容消失 | 重新导入并核对。未下载的结果不会自动保存；已下载文件仍由你自行保管。 |

## 它暂时不做什么

SheetCheck 不处理一单多次收款、多单合并收款、重复编号自动汇总、退款、手续费、负金额、跨币种换算或模糊编号匹配。遇到这些业务，需要先明确适合的核对口径；不要为了通过检查删除真实记录。

本机使用时，文件交给本机服务处理；应用默认不把上传内容和结果保存成业务文件。下载报告会包含原始业务字段，请按原账表的敏感程度保管。页面本身不替代业务调查、会计判断或资金结论。
