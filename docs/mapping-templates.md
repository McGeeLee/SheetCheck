# 字段映射模板

1.1.0 提供可选的 JSON 模板，适合每次导出结构相同、只更换数据内容的两张表。它保存两侧列号、格式、表头行位置、总列数、CSV 编码与分隔符，以及币种和固定 v1 规则。它不保存文件名、路径、工作表名、表头文字或哈希、业务编号、金额、原始行、文件哈希、期间或确认状态。

## 保存和应用

1. 导入两侧文件，选择工作表、表头和 CSV 读取参数，检查预览并选择编号列及金额列。
2. 在规则区域勾选“使用映射模板（可选）”，点击“保存当前映射模板”。固定文件名为 `sheetcheck-mapping-v1.json`，这是配置文件，不是核对报告。
3. 下次先导入新的两份文件并设置读取参数，再上传模板 JSON。上传本身不会改变当前选择。
4. 点击“应用到当前两份文件”。两侧格式、表头行、列数及 CSV 参数均匹配后，才一起应用两侧映射和币种。
5. 重新检查预览和映射示例，填写期间，确认币种与期间，再运行核对、生成报告。

即使模板与当前映射相同，显式应用也会撤销旧结果和旧报告，清空期间与两项确认，并重置查询、分类、筛选、分页和来源详情。输入或解析参数改变会清除已上传模板，不能默默自动套用到下一份文件。重新开始清空全部模板会话状态。没有模板数据库或默认磁盘保存。

## 结构匹配的限度

模板不保存列名，因此不能识别“列数相同但编号列与金额列换了顺序”等变化。结构检查成功只说明配置可用，不能证明字段含义正确。应用后必须复查两侧映射示例，币种和期间也仍由使用者确认。XLSX 工作表须手动选择，模板不会按旧工作表名自动切换；CSV 的编码、分隔符和表头行须先设置一致。

如果任一侧不匹配，应用整体失败，不先改变另一侧映射。文件本身改变仍按既有规则使旧结果失效。修正当前读取参数或重新选择字段后再试，不手动放宽核对规则。

## JSON 与错误

模板独立上限为 **16 KiB**。页面上传控件的传输限制为 1 MiB，但超过 16 KiB 的内容不会进入应用；核心解析器也独立检查字节上限。格式为严格 UTF-8 JSON，schema 版本为 1，仅接受约定字段；重复键、深层嵌套、浮点列号、布尔列号、未知字段、不支持币种、越界列号以及任何规则变更均拒绝。错误提示和日志不回显模板原文或上传文件名。

`TEMPLATE_INVALID` 表示模板格式或字段无效，应使用本程序重新导出的文件。`TEMPLATE_STRUCTURE_MISMATCH` 表示当前两侧结构或 CSV 参数不符，应检查读取设置与字段。`TEMPLATE_TOO_LARGE` 表示超过 16 KiB。模板不执行脚本、公式或路径访问，不覆盖源文件，也不能改变容差为 0、两位小数、一对一和两侧问题隔离规则。

实现位于 [纯模板模块](../sheetcheck/mapping_templates.py) 和 [页面](../app.py)。验证通过真实上传控件的 AppTest 与纯内核测试完成；未触发浏览器文件下载或重复权限确认。完整记录见 [v1.1 验证](v1.1-verification.md)。
