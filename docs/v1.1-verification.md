# v1.1.0 验证与 GitHub 交付

日期：2026-10-24（Asia/Singapore）。本版在已完成的 v1 基线上增加可选映射模板，并建立 GitHub 源码仓库、补齐本地回归与待启用的 CI 模板。核对规则 `v1`、报告格式 `m2-v1`、输入容量和精确依赖锁均不变。此前下载录像不补录的用户决定继续有效；没有执行浏览器下载或提出新的下载权限确认。

## 新增行为与验证

模板为有大小上限、严格字段白名单的 JSON，只复用列号、结构、CSV 参数、币种和固定规则，不保存文件名、表头、工作表名、业务数据、期间或确认。上传不自动应用；用户明确应用且两侧结构均匹配后，才一次性更新映射，撤销旧结果及报告，清空期间和确认，重置筛选及分页。列数相同不保证含义相同，页面要求复查示例。操作与限制见 [模板说明](mapping-templates.md)。

## GitHub 与交付范围

仓库为 [McGeeLee/SheetCheck](https://github.com/McGeeLee/SheetCheck)，默认私有。应用本身仍只运行在本机；创建源码仓库不把业务处理变成云服务。Git 跟踪源代码、测试、虚构样例、文档以及明确允许的历史虚构验收文件。虚拟环境、85 MiB wheelhouse、本地交付 ZIP、真实输入目录和以后生成的普通输出不进入 Git。

[Actions 配置模板](ci/github-actions.yml) 已做 YAML 和 shell 语法静态检查，计划在 push、PR 和手动触发时运行完整测试及独立样例导出；使用只读权限、固定 action 提交 SHA、无持久化 checkout 凭据、明确超时。托管 runner 配置为 `macos-15` arm64 / Python 3.12.10，原因及官方依据见 [开发说明](development.md)。

**GitHub CI 尚未启用，也没有运行通过的证据。** 2026-10-24 首次推送时，GitHub 拒绝通过现有 OAuth 凭据写入 `.github/workflows/ci.yml`，原因是缺少 `workflow` scope。没有申请额外授权；模板改为保存在 `docs/ci/`，因此源码推送不需要工作流写权限。它不在 `.github/workflows/` 中，不会自动触发。将来若主动决定启用，应使用具备所需权限的身份安装模板，并以实际 [Actions 结果](https://github.com/McGeeLee/SheetCheck/actions) 验证；静态模板与本地测试不能替代远程执行证据。

本地完整交付包由 `scripts/build_delivery.py` 生成 `deliveries/SheetCheck-1.1.0.zip`，不覆盖已有 1.0.0 包；文件清单为 `docs/v1.1-delivery-manifest.json`，外置校验回执为 `docs/v1.1-package-verification.json`。校验实际 ZIP 的成员集合、CRC、逐文件 SHA-256 和新目录解压后的内容。回执不收入自己描述的包，避免哈希自引用。源码克隆需先按锁文件取得依赖，不能把本机已有 wheelhouse 宣称为 Git 内置资源。

## 保留的边界

v1.0 的 20 个容量边界、10k/50k 性能、应用范围断外网、原生 Excel 与演示均保留其真实版本和原始记录，见 [M4 总验收](m4-verification.md)。本版未重新执行这些大规模或原生软件项目；没有因为规则未变而伪称全部重新测过。新的样例与完整回归证明本版所执行的功能范围，不能扩大成 Windows、Linux、Intel Mac、WPS、LibreOffice、整机物理断网、并发会话或所有最大维度组合的兼容保证。

历史下载、Excel 观察与新版视频是独立证据，用户已接受不补录下载的限制；[收尾记录](m4-closeout.json) 不改写。映射模板结构匹配无法检测同列数的语义或顺序变化；它必须经人工复查并重新确认后才能核对。原有日志、会话留存、逻辑取消和静态报告限制继续有效。
